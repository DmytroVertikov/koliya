# Колія: поездом из Украины и в Украину

Сайт на GitHub Pages + Supabase, четыре языка: RU (корень), UK, EN, PL (папки `uk/`, `en/`, `pl/`).

Публичный сайт читает варианты маршрутов из базы Supabase. Править их можно в админке `/admin/`. Страницы маршрутов и главная собираются из шаблонов скриптом `build.js`.

## Запуск (≈15 минут)

1. **База.** Создайте проект на supabase.com (бесплатно). Откройте SQL Editor и по очереди выполните файлы `schema.sql`, `seed.sql` (в нём уже загружены все маршруты) и `i18n.sql` (таблица текстов сайта, формы названий станций и тексты страниц маршрутов).
2. **Админ.** В Supabase: Authentication → Users → Add user (ваш email и пароль). Затем Authentication → Sign In / Providers → отключите **Allow new users to sign up**, иначе зарегистрироваться сможет любой.
3. **Ключи.** Project Settings → API. Скопируйте Project URL и anon public key в `config.js`. Эти ключи публичные, безопасность обеспечивают правила RLS из `schema.sql`.
4. **Сборка.** Установите Node.js и выполните `node build.js` (подробнее ниже).
5. **GitHub.** Создайте репозиторий `koliya`, загрузите все файлы из этой папки, откройте Settings → Pages → Source: Deploy from a branch → `main` / root.
6. Сайт будет по адресу `https://koliya.org/` (через CNAME и свой домен; без домена: `https://<ник>.github.io/koliya/`), админка по адресу `.../admin/`.

## Как устроена сборка

Готовые `.html` страницы **руками не правятся**: они создаются командой

```
node build.js
```

Все переводы лежат в базе и правятся в админке. `node sync.js` забирает их в файлы-снимки (`i18n.db.json`: тексты интерфейса и станции, `routes.db.json`: направления и тексты их страниц) и запускает `build.js`. Если базы не видно, берутся прежние снимки. Сборка берёт шаблоны `route.src.html` и `index.src.html`, переводы из снимков и список страниц из `routes.db.json` (таблица `route_pages`). Результат:

- `kyiv-warsaw.html`, `warsaw-kyiv.html`, `kyiv-krakow.html`, `krakow-kyiv.html` и `index.html` в корне (RU);
- те же страницы в `uk/`, `en/`, `pl/`;
- `dict/ru.js`, `dict/uk.js`, `dict/en.js`, `dict/pl.js`: словари для браузера (подключаются на страницах вместо прежнего `i18n.js`);
- `pages.js`: список страниц для браузера;
- `sitemap.xml`.

После правки переводов в админке, а также `route.src.html` или `index.src.html` запустите `node sync.js` (он же соберёт сайт) и загрузите изменённые файлы на GitHub. Если правите только `common.js` или `style.css`, пересборка не нужна.

Имена шаблонов должны быть ровно `route.src.html` и `index.src.html` (не `route_src.html`).

Сборка детерминированная: версия `?v=…` у `style.css` и `common.js` считается от их содержимого, времени сборки в страницах нет. Повторный запуск `node build.js` без изменений ничего не меняет, а правка одного текста меняет только затронутые страницы. После выкладки браузер или GitHub Pages могут несколько минут отдавать старые файлы: проверяйте через Ctrl+F5.

## Как править

- **Вариант маршрута** (админка). Одна строка, части разделяются `||`:
  `@ Киев 19:29 > Варшава 10:24 ; 14 ч 55 мин ; 1 пересадка || 019К: Киев 19:29 > *Хелм 05:00 || IC 12010: *Хелм 06:34 > Люблин 07:44 > *Варшава Центральная 10:15`
  - `@ …` шапка карточки: откуда > куда ; в пути (необязательно) ; плашка (необязательно);
  - дальше каждый поезд отдельной частью, станции через `>`, звёздочка `*` выделяет станцию крупным шрифтом;
  - пересадка между поездами добавляется автоматически. Админка проверяет формат прямо при вводе.
- **Какие варианты показывает страница.** Страница «A → B» берёт варианты, у которых в шапке карточки город отправления A, а город прибытия B (по начальным буквам названия). Админка показывает варианты прямо внутри направления; те, что не подходят ни к одной странице, собраны в разделе «Варианты без страницы». Варианты видны на сайте сразу, настройки и тексты страниц — после «Пересобрать сайт».
- **Скрыть поезд**, не удаляя: «Показывать: Скрыт».
- **Новая страна:** админка поездов → вкладка «Страны» (код, флаг, названия на четырёх языках, падежи для главной), затем «Пересобрать сайт», затем «Направления и варианты» → «Новое направление».
- **Тексты сайта и переводы:** админка поездов (`/admin/trains.html`), вкладка «Тексты». Одна строка на ключ, колонки ru / uk / en / pl; пустой перевод заменяется русским. Названия стран правятся во вкладке «Страны» (они хранятся в `ui_texts` под ключами `cn.<код>` и `cn.<код>.gen`).
- **Блок «Как купить билеты»:** «Направления и варианты» → направление → «2. Как купить билеты». Никаких опций: вы сами задаёте количество блоков и их порядок (↑ ↓), у каждого блока отметку «прямой поезд» (зелёный блок), заголовок, пункты и кнопки со ссылками. Все тексты вносятся вручную на четырёх языках, переключатель RU / UK / EN / PL над блоками. Поле без перевода подсвечено красным и отмечено «нет перевода», рядом с языком стоит счётчик, а в списке направлений у страницы появляется метка «нет перевода: uk, en»; на сайте до перевода показывается русский текст. Готовые блоки лежат в выпадающем списке «Шаблон…» (таблица `buy_templates`): «Подставить» копирует шаблон в блок, дальше его можно править, «В шаблоны» сохраняет блок в список (то же название — перезапись), «Удалить шаблон» убирает его из списка (блоки на страницах не меняются). Так же работает примечание под блоками. Данные страницы лежат в `route_pages.buy`: `{note, blocks: [{direct, h, steps, btns}]}`; нет блоков — раздел на странице не выводится. Сборка — функция `buyHtml` в `build.js`.
- **Тексты страницы маршрута** (заголовок, описание, подзаголовок и т.д.): вкладка «Направления и варианты» → выбрать направление → «Настройки страницы».
- **Название станции на другом языке** и формы «в Хелме» / «у Хелмі» / «w Chełmie»: вкладка «Станции». Без перевода станция показывается по-русски (в консоли браузера появится сообщение).
- Сайт получает изменения после нажатия «Пересобрать сайт» в админке (запускает GitHub Actions: `.github/workflows/rebuild.yml` делает `node sync.js` и коммитит результат), обычно через 1–2 минуты. Вручную то же самое: `node sync.js` и загрузка файлов на GitHub.

## Полезная информация на главной

Телефоны поддержки, кнопки «где купить билет» и аэропорты правятся в админке поездов, вкладка «Главная» (таблица `home_links`). Заголовки и пояснения блока лежат во вкладке «Тексты» (ключи `ix.help.*`, `ix.buy.h`, `ix.fly.*`). На сайте после «Пересобрать сайт».

## Популярные маршруты на главной

В блоке «Популярные маршруты» у каждой страны сразу видны только страницы с галочкой «на главной» (админка → «Направления и варианты», галочка у направления), остальные лежат в раскрывающемся списке. Если у страны нет ни одной отмеченной страницы, показываются все её маршруты. Но на виду остаётся не больше 5 строк (по 5 маршрутов «из Украины» и «в Украину»), остальное уходит в «Ещё маршруты» автоматически. Страна, у которой больше 5 маршрутов, показывается во всю ширину в две колонки (слева «из Украины», справа «в Украину»). Хранится в `route_pages.popular`, на сайте после «Пересобрать сайт».

## Пометки у поездов

Пометка рядом с номером поезда выбирается в админке: «Поезда» → поезд → поле «Пометка» (сидячий интерсити, по нечётным числам, по чётным числам). Хранится в `trains.badge`, на сайт попадает после «Пересобрать сайт» через `pages.js` (`CFG.TRAIN_BADGES`). Тексты пометок лежат в `ui_texts` под ключами `seat`, `odd`, `even`. Новый вид пометки (кроме этих трёх) требует кода: ограничение `trains_badge_check` в базе, иконка `ICON` в `common.js` и стиль в `style.css`.

## Пограничный контроль

Для страниц Киев → Краков и Краков → Киев под плашкой пересадки в Перемышле выводится строка про пограничный контроль. Она включается флагом `border` в `ROUTES` в `build.js`:

- `border: "after"`: «После прибытия в Перемышль происходит пограничный контроль» (Киев → Краков);
- `border: "before"`: «Перед отправлением из Перемышля происходит пограничный контроль» (Краков → Киев).

Тексты лежат во вкладке «Тексты» под ключами `border.after` и `border.before`. Без флага строка на странице не выводится.

## Новая страница маршрута

Создаётся в админке: вкладка «Направления и варианты» → «Новое направление» (сразу две страницы: туда и обратно, на четырёх языках). Параметры блока покупки и тексты страницы правятся там же (выбрать направление → «Настройки страницы»), а её варианты — на соседней вкладке «Варианты» того же направления. Затем `node sync.js` и загрузка файлов на GitHub. Адрес страницы попадёт в `sitemap.xml` и на главную автоматически, править `build.js` и `config.js` не нужно.

## Файлы

- `index.src.html`, `route.src.html`: шаблоны главной и страниц маршрутов;
- `page.src.html` и `static-pages.js`: шаблон и тексты служебных страниц (`privacy.html`, `about.html`, `contacts.html` на четырёх языках). Тексты правятся в `static-pages.js`, затем `node build.js`. Если на сайте появится реклама или статистика, обновите раздел «Реклама и статистика» в политике конфиденциальности;
- `build.js`: сборка языковых версий, словарей `dict/` и `sitemap.xml`;
- `sync.js`: выгрузка направлений, текстов и станций из базы и запуск сборки;
- `pages.js`: список страниц маршрутов (создаётся сборкой, руками не править);
- `i18n.db.json`, `routes.db.json`, `options.db.json`: снимки данных из базы (создаются `sync.js`). `options.db.json` (варианты маршрутов) нужен, чтобы карточки расписания лежали прямо в HTML и были видны поисковикам; код карточек (`renderCards` в `common.js`) один и для сборки, и для браузера, браузер потом обновляет их свежими данными;
- `dict/`: словари для браузера (результат сборки);
- `common.js`: общий код (разбор формата вариантов, карточки, пометки поездов, футер);
- `style.css`: оформление;
- `config.js`: ключи Supabase;
- `index.html`, `uk/`, `en/`, `pl/`, `kyiv-warsaw.html` и другие страницы маршрутов, `sitemap.xml`: результат сборки;
- `supabase/functions/rebuild-site/`: функция Supabase для кнопки «Пересобрать сайт» (код, секреты и развёртывание: README рядом);
- `admin/trains.html`: админка (поезда, направления с вариантами, станции, страны, главная, тексты); `admin/index.html` только перенаправляет на неё;
- `schema.sql`, `seed.sql`, `i18n.sql`: база.

## Подвал сайта

Дата в строке «Информация на странице обновлена» ставится автоматически: это дата последнего изменения вариантов маршрутов в базе. При сборке её берёт `node sync.js` (`i18n.db.json` → `meta.updated`), а в браузере `common.js` уточняет по базе, так что после правки варианта дата меняется сразу. Дату в тексте `f2b` вручную менять не нужно (можно писать `{date}`). Источники данных (Укрзалізниця, PKP Intercity, RegioJet, České dráhy, ZSSK, MÁV, ÖBB, CFR Călători, Deutsche Bahn) заданы списком `FOOT_SRC` в `build.js` и `common.js`; подпись к ним — ключ `f.src` во вкладке «Тексты».
